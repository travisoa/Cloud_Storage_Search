# 后台执行约定

入口为 `scripts/media.py`。对话负责理解请求及解决歧义，后台模块负责可重复的数据核对和操作；不需要浏览器。用户明确转存/补齐请求即为该任务的执行授权，查询/预览请求只读。

## 执行范围

影库总目录已由用户指定。优先复用唯一匹配的作品目录；新作品只在现有且明确的电视剧分类内创建，不把总影库根目录默认为电视剧分类。多个同名作品、多个分类、未知原集号或等价版本返回待确认。

元数据提供预计播出信号。过了预计时间不等于已经播出或网盘有资源；执行前必须实际枚举分享文件并匹配缺集。字幕不代表视频已有，未知编号不能当不存在直接补。

分享中的纯数字视频名默认仍待确认。对话明确确认版本及季集后，可向工作流传入 `source_episode_mapping`，按候选哈希绑定真实文件名、大小和季集，再由 `source_selection` 固定版本；名称、大小、来源或编号不符立即停止。该映射只作用于已确认的来源，不改变旧影库的解析，也不按排序猜集号。

正式任务保存 `resolved_request`、候选快照与确认记录，绑定当前影库根目录；不接受任意任务路径或更换根目录后的重放。`confirm` 从快照构建映射，`resume` 复用同一任务，只有带执行参数才可写云盘。身份、任务和偏好的读写共用影库任务锁，凭据和分享令牌不进入快照。

外部核实的译名用 `bind-series` 保存，按元数据来源、作品 ID、年份定位，并记录远端原名与 HTTPS 依据。运行时须再次核对远端 ID、年份、原名才扩充别名；新确认的作品不采用搜索第一条。同名多个作品仍需明确年份。偏好属于该作品，不能自动提升为所有作品的设置。

## 订阅与周期检查

`watch add --task-id ...` 从正式任务导入已确认的作品和季；`watch list/status` 查看订阅，`watch pause/resume` 控制后续检查。订阅存于私有的 `runtime/subscriptions.json`，身份包含主元数据来源、作品 ID、年份、季和影库根目录；重复添加沿用同一订阅。已暂停的订阅不因 `--force` 被执行。

`watch run --due` 只检查启用且到期的订阅，`--force` 可提前检查。默认只读；只有订阅自身 `auto_save` 已获授权、命令带 `--apply` 且没有阻断时才可写入。`--plan` 优先于 `--apply`。Codex heartbeat 负责周期唤醒，调用正式入口；没有变化、没有到期任务或任务锁忙时保持安静，仅对真实新增、失败或需要用户处理的变化通知。检查不发送 Telegram。

首批授权仅覆盖《白色黑手党时代》S01、每 6 小时、原已选 4K 来源。新增作品、季或写入范围需对应授权，不能由日历或搜索结果自行扩大。

已选分享以规范 URL、来源哈希、分享内父目录、路径及画质依据保存，不保存分享 token。先检查该目录；缺集资源不足时才调用 PanSou 补充。相同优先级的多个版本、季集歧义或不满足画质偏好时不自动降级。确认后的新来源可成为后续检查来源，不能把未选搜索结果全部记为可信来源。

一次任务的数字集号确认不自动授权所有后续文件。订阅可显式保存已有确认的持续规则：来源哈希、同一分享父目录、季和画质须全部一致，才把后续纯数字视频名解释为该季集号。该规则由原任务确认与转存凭据支持；换目录、换源、换季或画质不符时重新确认，不能仅凭标题相似或文件顺序猜编号。

每次检查分别记录元数据日程、实际分享文件和真实影库库存。仅转存已匹配的缺集；同次只找到部分缺集时保留其余待找集数。认证、风控、未知写入、身份或来源冲突会阻断自动写入；后续健康只读检查不自行清除阻断。`watch resume ID --clear-block` 先只读对账，确认可恢复后清除阻断；未知转存仍沿用原任务 ID 与真实 fid 恢复，不重新提交保存请求。

## 命名与媒体信息

作品目录与文件共用同一剧名前缀，已有目录优先；新目录默认 `剧名 (年份)`，文件为 `同一前缀 S01E01 [2160p HEVC HDR10].mkv`。季集号始终保留。字幕沿用视频主文件名并保留语言、forced 和原扩展名。实际不存在的媒体标签不补写。

标签优先来自文件名，其次为最近的父目录；4K/UHD 归一为2160p，同层冲突保持未知。报告保留标签文本及来源，当前没有下载或探测码流。命名形式参考 [Infuse Metadata 101](https://support.firecore.com/hc/en-us/articles/215090947-Metadata-101)，封面、刮削和播放需另行验证。

`normalize-saved` 默认只生成计划；执行必须同时匹配原转存凭据、完成日志、原目录快照之外的真实新 fid、源文件身份与大小。只改这些新文件，不改目录、不整理旧资源。每次改名前写独立命名意图，未知结果先按 fid 回查；成功后同步原日志目标名称，以便后续对账。

## 恢复与审计

写请求前持久化意图；提交后记录远端任务 ID 和真实新文件 ID。只改名本次保存的、原目录快照中不存在且重新列目录核验成功的文件。改名前再次检查覆盖冲突。发生未知结果先 GET 对账，不重新 POST 转存。

Provider 在保存 POST 返回合法任务 ID 后、首次轮询前调用持久化回调，先记录任务 ID、目标目录和源 fid。落盘失败即停止，不继续轮询或重发写入。`reconcile` 只用 GET 核对任务状态和实际文件，可更新本地日志；未改名返回 `READY_TO_RENAME`，由后续已授权 `resume --apply` 继续。

建目录返回的真实 fid、名称和父目录在读取核验前持久化。目录列表更新稍慢时，最多只读复查3次、间隔0.3秒；恢复必须精确核验已记录 fid。没有返回 fid 的旧记录保持未知，由对话依据真实目录另行对账，不重复创建。

幂等身份基于网盘账号范围、元数据来源与作品 ID、季、影库根目录；译名或目标目录参数的变化不能绕过未完成记录。凭据、分享 token 不进入审计。配置或身份变化与旧操作冲突时停止，保留文件和证据。

## 当前限制

精确匹配、版本策略、体检及压缩包的操作边界见[影库维护说明](media-maintenance.md)。压缩包不自动转存或入库；单包解压仅作用于明确选中的库内源包和本次创建的空暂存目录。此端点尚未完成真实解压验收。

新网盘建库及可选导入见[建库与导入说明](library-bootstrap.md)。初始化只创建目录；旧资源默认保护，不能借初始化自动移动或命名。当前网盘测试目录具有 `test_only` 标记，仅允许初始化及扫描预览，不能承接转存或旧资源迁移。

只实现夸克写入适配器；其他网盘可按 StorageProvider 接口扩展。电影流程只接受 TMDB 身份，不做合集、分段（CD1/CD2）或导演剪辑版的自动区分，这些候选列入待确认。综艺特别篇、多集容器、绝对编号和复杂季集顺序保守交给对话确认。追更只覆盖明确订阅，不提供下载转码、自动删除、跨网盘搬运、播放器或独立刮削器。
