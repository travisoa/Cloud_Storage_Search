# 执行约定

统一入口为 `scripts/media.py`。对话负责明确请求和消除歧义，执行模块负责库存核对与操作执行，全程不依赖网页。明确的转存或补齐请求即为对应任务的执行授权；查询和预览保持只读。

## 执行范围

默认影库操作限于已配置的影库根目录及其子目录。用户明确选择的新网盘、父目录及导入源通过正式 `library` 流程单独授权，边界见[建库与导入说明](library-bootstrap.md)。优先复用唯一匹配的作品目录：定位时只打开分类及地区、年份等分组目录，同层出现作品名即不再深入，同层的同名或带限定词目录仍按歧义处理；新电视剧、电影目录分别建于已确认的对应分类，不将影库根目录视为分类。作品身份、分类、季集或等价版本存在歧义时返回待确认。

元数据提供预计日程，实际分享文件决定资源可用性，影库目录决定已有库存，详见[来源与日程边界](metadata-assessment.md)。字幕不计为已有视频，未知编号须先核对，不能直接计为缺集。

认证失败、验证码或风控立即停止。单条分享失效或受限（41xxx）仅跳过该分享。凭据来源、存储和更新方式见[凭据配置](credentials.md)。

分享中的纯数字视频名默认待确认。明确版本及季集后，`source_episode_mapping` 按候选哈希绑定真实文件名、大小和季集，`source_selection` 固定版本；名称、大小、来源或编号不符即停止。映射仅作用于已确认来源，不改变既有影库的解析，不按排序推断集号。

正式任务保存 `resolved_request`、候选快照与确认记录，并绑定影库根目录；不接受任意任务路径或跨根目录重放。`confirm` 从快照构建映射，`resume` 继续同一任务，两者带 `--apply` 才写云盘。身份、任务和偏好的读写共用影库任务锁，凭据和分享令牌不进入快照。

外部核实的译名通过 `bind-series` 保存，按元数据来源、作品 ID、年份定位，并记录远端原名与 HTTPS 依据。运行时再次核对远端 ID、年份和原名后才采用别名；搜索排序不作为身份依据，同名作品须明确年份。作品级偏好不扩展为全局设置。

## 订阅与周期检查

`watch add --task-id ...` 从正式任务导入已确认的作品和季；`watch list/status` 查看订阅，`watch pause/resume` 控制后续检查。订阅存于私有的 `runtime/subscriptions.json`，身份包含主元数据来源、作品 ID、年份、季和影库根目录；重复添加沿用同一订阅。已暂停的订阅不因 `--force` 被执行。

`watch run --due` 仅检查启用且到期的订阅，`--force` 可提前检查，不绕过暂停、授权或阻断。默认只读；订阅的 `auto_save` 已获授权、命令带 `--apply` 且无阻断时才写入。`--plan` 优先于 `--apply`。Codex heartbeat 通过正式入口周期唤醒；无变化、无到期任务或任务锁被占用时不通知，仅报告新增、失败或需要用户处理的变化，不发送 Telegram。

授权范围由已确认的订阅及其关联任务确定。作品、季、来源、检查频率或写入范围变化均须有对应用户授权，不因日历、搜索结果或任务恢复自动扩大。

已选分享记录规范 URL、来源哈希、分享内父目录、路径及画质依据，不保存分享 token。优先检查已选目录，资源不足时通过 PanSou 补充。等价版本、季集歧义或画质不符保持待处理；仅已确认的新来源可用于后续检查，未选搜索结果不自动纳入。

单次数字集号确认不覆盖后续文件。订阅可显式保存持续映射规则，由原任务确认与转存凭据支持；后续文件须同时匹配来源哈希、分享父目录、季和画质，才将纯数字文件名解释为该季集号。目录、来源、季或画质变化时重新确认，标题相似与文件顺序不作为编号依据。

订阅另有三项默认关闭的来源策略，仅由 `watch add` 显式开启或关闭（`--trust-share-title` / `--no-trust-share-title`、`--wait-on-uncertain` / `--block-on-uncertain`、`--archive-auto largest|off`）；重复添加时未指定的选项保持原值。

- `trust_share_title`：未选来源的文件路径不含剧名时，满足以下全部条件仍可接受：搜索结果标题含剧名或别名（分享根目录名属于路径，已由原检查覆盖）；文件名自带本季 SxxEyy，或路径中恰有一个季目录（`Season 1`、`S01`、`第一季`）与订阅季一致且文件名给出集号（含纯数字）；同一分享内该集通过画质筛选的候选只有一个。季目录与订阅季不一致、存在多个季目录或同一分享有多个候选时仍为不确定；不同分享之间按原评分择优，并列仍为不确定。
- `wait_on_uncertain_source`：来源或集号不确定的集数只在本轮等待（`WAITING`，原因 `subscription_source_uncertain_retry_next_cycle`），下个检查时段重新搜索；同轮已确定的其他集照常转存。认证、风控、写入结果未知、元数据冲突及目录冲突仍阻断订阅。
- `archive_auto: largest`：仅处理缺集。压缩包须为受支持格式的单文件包；集号取自包名（SxxEyy、Exx、第N集或纯数字），包名无标记时取自所在目录名，路径中的季目录须与订阅季一致；须通过画质或版本策略，同一分享内该集只有一个此类包，且严格大于该集其他压缩包及所有符合画质的视频候选，并列时为不确定。执行沿用 `archive fetch` 与隔离解压；解压结果须恰有一个视频，且与包名集号不冲突。视频及同名字幕先在解压目录内按统一命名改名，再移入作品现有季目录；移入前核对重名及该集是否已出现。每步写入意图先落盘，结果未知时只读回、不重发。原包、暂存目录及清空后的解压目录按 `archive_cleanup` 处理：`recycle` 移入回收站，`ask` 报告清理命令，`keep`（默认）保留；解压目录仍有其他文件时保留。季目录尚不存在时该集等待。不比较或替换影库中已有的剧集文件。

转存或压缩包入库成功后，所用分享（含分享内目录、路径及画质依据）追加到订阅来源，原有来源保留在前，失效来源不被替换。`watch add --source-url URL --append-source` 以同样方式追加导入的来源；不带 `--append-source` 时替换已记录来源。

每次检查分别记录元数据日程、实际分享文件和影库库存，仅转存已匹配缺集，未找到的集数继续保留。认证、风控、未知写入、身份或来源冲突（未开启 `wait_on_uncertain_source` 时）会阻断自动写入，后续只读检查不自动清除阻断。`watch resume ID --clear-block` 先只读对账，可恢复后才清除阻断；未知转存按原任务 ID 与真实 fid 恢复，不重新提交保存请求。

## 命名与媒体信息

作品前缀优先沿用真实作品目录名，目录本身不改名；新目录默认 `剧名 (年份)`。剧集前缀紧接 `SxxExx`，标签按分辨率、动态范围、音轨顺序以 `_` 连接，例如 `名称S01E01_1080P_HDR10_DDP5.1.mkv`；没有标签时为 `名称S01E01.mkv`。电影例如 `片名 (年份)_2160P_DV_TrueHD7.1.Atmos.mkv`。字幕沿用视频主文件名并保留语言、forced 和原扩展名。

媒体字段来自明确的发布标签：文件名优先，缺失时取最近的有标签父目录；连写标签（如 `4KHDR60FPS`）仅在整段均由已知标签组成时拆开识别；同层冲突保持未知，缺失或冲突字段逐项省略，不留占位符。4K/UHD 输出为 `2160P`；保留 `HDR10`、`HDR10+`、`HLG` 细分，Dolby Vision 输出 `DV`，仅显式 SDR 标签输出 `SDR`。音频格式、声道及 Atmos 须有明确标签，不由其他字段推断。视频编码保留为内部选源依据，不输出到文件名。报告保留原标签与来源，标签解析不构成码流探测。

此格式用于新生成的命名计划，不自动迁移既有文件或旧任务日志；旧资源须按已授权的整理计划执行。命名形式参考 [Infuse Metadata 101](https://support.firecore.com/hc/en-us/articles/215090947-Metadata-101)，不代表封面、刮削或播放已通过验证。

`normalize-saved` 默认只生成计划；执行必须同时匹配原转存凭据、完成日志、原目录快照之外的真实新 fid、源文件身份与大小。只改这些新文件，不改目录、不整理旧资源。每次改名前写独立命名意图，未知结果先按 fid 回查；成功后同步原日志目标名称，以便后续对账。

## 恢复与审计

写请求前持久化意图，提交后记录远端任务 ID 和真实新 fid。转存后的自动改名仅作用于该任务新增、原目录快照中不存在且经真实目录核验的文件，改名前再次检查重名冲突。结果未知时先通过读取对账，不重复提交转存。

Provider 在保存 POST 返回合法任务 ID 后、首次轮询前调用持久化回调，先记录任务 ID、目标目录和源 fid。落盘失败即停止，不继续轮询或重发写入。`reconcile` 只用 GET 核对任务状态和实际文件，可更新本地日志；未改名返回 `READY_TO_RENAME`，由后续已授权 `resume --apply` 继续。

目录创建返回的真实 fid、名称和父目录在读取核验前持久化。目录列表延迟时最多只读复查 3 次，间隔 0.3 秒；恢复须精确核验已记录 fid。未返回 fid 的旧记录保持未知，依据真实目录另行对账，不重复创建。

幂等身份基于稳定网盘连接引用、元数据来源与作品 ID、季、影库根目录。连接引用区分 AList 挂载、命名凭据文件及默认环境变量来源，不以影库根目录或 Cookie 哈希代替；Cookie 续期不改变同一连接的身份。该引用不能单独证明更换后的凭据仍属同一真实账号，替换文件凭据须沿用影库目录核验。译名或目标目录参数的变化不能绕过未完成记录。凭据、分享 token 不进入审计。账号范围阻断只返回原因，不覆盖原任务候选或转存回执。

旧任务未记录连接范围时禁止直接写入；新范围发现同作品的旧根目录范围日志时返回 `legacy_account_scope_requires_confirmation` 及 `adopt-scope` 命令，不自动迁移或重新提交，只重新生成计划不能解除阻断。`adopt-scope JOB_KEY` 默认只读，仅接受已完成记录：当前连接须在记录目录中读回其已核验的新 fid 且大小一致（名称可因已授权整理而不同）；任一 fid 大小或类型冲突、或无一可见时保持阻断。`--apply` 只在本地日志中按当前范围复制该记录并注明来源，原记录保留，不写云盘。未完成的旧记录不迁移。

手工任务的 `as_of` 固定为原计划时间，`confirm` / `resume` 不自动扩展新到期集。需要检查当前日期时使用 `replan TASK_ID`：保留作品与目标目录身份，创建新只读任务，重置时间、候选选择、数字集号映射及替换/回收指令；原任务和回执保留。检查新计划后另行明确授权写入。订阅每轮使用本轮时间；空 `ready` 记录恢复后仍重新生成本轮计划。

## 能力边界

精确匹配、版本策略、体检及压缩包的操作边界见[影库维护说明](media-maintenance.md)。压缩包不自动转存或入库；单包解压仅作用于明确选中的库内源包和该任务创建的空暂存目录；原包及清空的暂存目录按 `archive_cleanup` 保留、回收或询问。

新网盘建库及可选导入见[建库与导入说明](library-bootstrap.md)。初始化仅创建目录，不自动移动或命名旧资源。标记为 `test_only` 的测试影库仅允许初始化及扫描预览，不承接转存或旧资源迁移。

写入适配器仅支持夸克，其他网盘需实现 `StorageProvider`。电影仅接受 TMDB 身份；合集、分段（CD1/CD2）、导演剪辑版、综艺特别篇、多集容器、绝对编号及复杂季集顺序均需明确核对。追更限于已授权订阅；媒体下载、码流探测、转码、跨网盘搬运、播放器及独立刮削器不在已实现范围内。除[授权替换剧集](media-maintenance.md#替换已有剧集的版本)可回收记录中的旧 fid 外，不执行自动删除。

模拟验证、真实操作验收及未解决限制统一记录于[验证报告](test-report.md)；本文不作为实时服务或云盘状态证明。
